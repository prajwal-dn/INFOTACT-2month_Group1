# Day 1 Notes - Environment Setup & Initial Logger

**Date:** 11 October 2026
**Branch:** Aman-Gaikwad

## Objectives
- Establish the Python environment for the CAN-Sentinel project.
- Create the initial `logger.py` script to parse raw SocketCAN `candump` output.
- Align with the team on the data schema.

## What Happened & What Was Done
The initial focus was on bridging the gap between the raw C-level SocketCAN output and Python. I set up a Python virtual environment to isolate dependencies. 

I wrote the first version of `logger.py`, which reads a text file containing `candump` output and uses Regular Expressions (Regex) to extract the core CAN frame data. During this, I mapped out how the classic CAN format looks (e.g., `(timestamp) can0 ID#DATA`). I successfully extracted the CAN ID, DLC (Data Length Code), and Payload, converting them into a standard CSV format.

## Key Findings & Decisions
- **CSV Schema Agreement:** We agreed on the standard columns: `timestamp`, `can_id`, `payload`, and `dlc`. This ensures the data generated by the environment matches what the ML model expects.
- **Parsing Challenges:** `candump` output can vary based on flags. Sometimes it includes a timestamp in parentheses, sometimes it doesn't. I ensured the regex was robust enough to handle the baseline format first, before worrying about edge cases.
